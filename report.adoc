= Лабораторна робота №1: Аналіз складності алгоритмів. Асимптотичні оцінки Від O та Little o
:stem: latexmath
:lang: uk

Вивчити стандартні класи складності алгоритмів, реалізувати обраний алгоритм і довести його відповідність заданим асимптотичним межам часу виконання.

== Завдання (Варіант 7)
* *Алгоритм:* Сортування вставками (Insertion Sort)
* *Категорія:* Просте сортування
* *Необхідна О (не хуже):* stem:[O(N^2)] (кращий випадок stem:[O(N)])
* *Строга границя о (строго швидше):* stem:[o(N^3)]

== Реалізація алгоритму (Java)

[source,java]
----
import java.util.Random;

public class InsertionSort {
    public static void sort(int[] array) {
        int n = array.length;
        for (int i = 1; i < n; i++) {
            int key = array[i];
            int j = i - 1;

            while (j >= 0 && array[j] > key) {
                array[j + 1] = array[j];
                j = j - 1;
            }
            array[j + 1] = key;
        }
    }
}
----

== Результати тестування (для N = 100 000)

На основі запуску програми було отримано такі часові показники:

|===
| Сценарій | Час виконання (секунди)

| *Кращий випадок* (вже відсортований масив)
| 0.000632 сек

| *Середній випадок* (випадкові дані)
| 1.092415 сек

| *Гірший випадок* (зворотний порядок)
| 4.089456 сек
|===

== Математичне обґрунтування складності
=== 1. Доведення верхньої межі Big O: stem:[O(N^2)]

Алгоритм містить два вкладені цикли: зовнішній `for` (виконується stem:[N-1] разів) та внутрішній `while`.

* *У гіршому випадку* (масив відсортований за спаданням), для кожного елемента на позиції stem:[i] внутрішній цикл робить stem:[i] порівнянь та зсувів.
* Загальна кількість операцій stem:[T(N)] є сумою арифметичної прогресії:

[stem]
++++
T(N) = \sum_{i=1}^{N-1} i = \frac{(N-1)N}{2} = \frac{1}{2}N^2 - \frac{1}{2}N
++++

За визначенням stem:[O]-великої, ми залишаємо лише старший член і відкидаємо константи, отже:

[stem]
++++
T(N) \leq C \cdot N^2 \implies T(N) = O(N^2)
++++

=== 2. Доведення строгої верхньої межі Little o від stem:[N^3]

Нам потрібно довести, що складність алгоритму росте строго повільніше, ніж функція вищого порядку stem:[f(N) = N^3], тобто stem:[T(N) = o(N^3)].

За математичним визначенням маємо перевірити границю відношення функцій при stem:[N \to \infty]:

[stem]
++++
\lim_{N \to \infty} \frac{T(N)}{N^3} = \lim_{N \to \infty} \frac{\frac{1}{2}N^2 - \frac{1}{2}N}{N^3} = \lim_{N \to \infty} \left( \frac{1}{2N} - \frac{1}{2N^2} \right) = 0
++++

Оскільки границя дорівнює stem:[0], це математично доводить, що швидкість росту нашого алгоритму є строго меншою за stem:[N^3], тобто stem:[T(N) = o(N^3)].
== Висновки

Під час лабораторної роботи було успішно реалізовано алгоритм сортування вставками
(Insertion Sort) без використання вбудованих бібліотек. Експериментальні заміри часу
повністю підтвердили теоретичні розрахунки: у кращому випадку алгоритм працює майже
миттєво, а у гіршому — час зростає квадратично. Математично доведено відповідність
асимптотичним межам stem:[O(N^2)] та stem:[o(N^3)].
